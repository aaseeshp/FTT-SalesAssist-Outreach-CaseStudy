Franklin Templeton · SalesAssist case study · working plan

One click on the email icon, one grounded draft

When a sales user clicks the email icon next to an advisor, SalesAssist pulls six data sources together and works out why this advisor needs contact now. It then drafts an email that uses only facts the data supports and lists the admin tasks the advisor's requests create. The user edits the draft and sends it themselves.

3 · Evidence rules

Traps planted in the sample data

The brief says to "take account of what a source actually supports". Each item below is a concrete case in the files. The POC should enforce each one in code and cover it with a test.

The newest Riverstone factsheet is the wrong one06 · D103 → P101A

D103 (released 11-05) is for Class A. Riley asked about Class I, so attach D101 and D102 instead.

Casey's requested factsheet does not exist yet06 · D104 internal

The only Oakbridge document is an internal presentation. Block it, tell the user, and raise an admin task to source an approved factsheet.

The webinar invite is not interest02 · ACT104 outbound, flag N

Jordan never replied. Do not write "following up on your interest in…".

A falling holding is not a redemption03 · Oakbridge −5,000

The sales file shows no redemption. The drop may be market movement, so leave it out of the email.

Missing records mean unknown03, 04 · A102, A103

Neither advisor has holdings or sales rows. Never write "you don't hold any of our funds".

Region is a hard boundary00 · U101=T1, 01 · A103=T2

Only Sam Lee can draft for Casey. For any other user the system returns nothing and calls no model.

Fund data is licensed and dated05 · as of 2026-10-31

Include the rating or return only when it adds substance, always with its date and disclosure text.

Tone comes from the relationship01 comments + 02 · ACT102

Riley prefers concise emails, so the draft is short with links rather than a long product pitch.

Birthdays are timing signals01 · Jordan 11-15, Riley 08-14

Jordan's is 4 days away and is offered as a separate note. Riley's has passed and is ignored.

5 · Proposed design

What happens after the click

Rules decide what is true and allowed. The language model only writes. That split keeps every claim traceable and lets the capability grow by adding new detectors.

  1. Check entitlement

    The user's region must equal the advisor's region. If not, stop before any data is fetched or any model is called.

    Rules · Access guard

  2. Assemble context

    Fetch all six sources by ADVISOR_ID in parallel and resolve products to share classes through the catalog.

    Rules · Source adapters

  3. Detect signals

    Pluggable detectors each emit a typed signal with evidence IDs, date, strength and caveats. Examples: open request, significant trade, firm move, upcoming birthday, new approved material.

    Rules · Signal engine

  4. Rank intents

    Score by type: an open commitment beats a timely trade, which beats a relationship touch. Weight by recency and size. Return one primary intent and up to two alternates.

    Rules · Intent ranker

  5. Build the fact pack

    Apply the evidence rules: attachable documents, dated fund data, banned inferences. Output only allowed facts, each with an ID.

    Rules · Evidence guard

  6. Draft

    The model receives the intent, fact pack and tone hints. It returns subject, body and the fact IDs each sentence relies on.

    LLM · Drafting agent

  7. Verify

    Every number, date, fund name and link in the draft must match the fact pack. Anything else is removed or the draft is regenerated.

    Rules · Claim checker

  8. Review in SalesAssist

    A side panel opens with tabs for each intent, "why this email" evidence chips, toggles to add or drop facts, a tone control, admin tasks and Copy. The user sends the email themselves.

    UI · Outreach panel
Making it instant. The brief says content must be available as soon as the user clicks. Steps 2–7 run ahead of time, overnight and whenever a source changes, and the results are cached per advisor. The click only runs the entitlement check and reads the cache, then refreshes in the background if the data is stale. If the model is unavailable, a template drafter fills the same fact pack, so the panel still opens.

7 · Decisions to confirm

Before Phase 0 starts

Stack

Python FastAPI backend with a light React or HTML front end, or a single Next.js app.

Recommend: Python + FastAPI. The rule engine and tests are easy for a reviewer to read.

Model provider

The brief welcomes Azure. A provider interface lets the deck show Azure as the target deployment.

Recommend: Claude via a provider interface, with the template fallback as the default demo mode.

Intents in v1

The brief asks which needs to support first.

Recommend: Fulfil request, Thank for trade and Firm move in v1. Meeting follow-up and birthday become alternates.
